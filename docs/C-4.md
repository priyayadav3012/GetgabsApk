# C-4 — `substring(3, 99)` crash on Indian phone numbers

## Problem

`_formatPhoneDisplay` in `WhatsAppCallingScreen` formatted `+91` numbers like this:

```dart
if (cleaned.startsWith('+91') && cleaned.length == 13) {
  return '+91 ${cleaned.substring(3, 99)} ${cleaned.substring(99)}';
}
```

A `+91XXXXXXXXXX` number is exactly 13 characters. `cleaned.substring(3, 99)` asks Dart to slice from index 3 to index 99, but the string only has indices 0–12. Dart throws:

```
RangeError (end): Invalid value: Not in inclusive range 3..13: 99
```

This crash fired every time the calling screen displayed a caller with an Indian number — which is the majority of the user base. The crash occurred in both the incoming call screen and the dialling screen.

## Fix

**File**: `lib/ui/pages/dashboard/chats/messages_ui/whatsapp_calling_screen.dart`

```dart
// BEFORE — out-of-range indices cause RangeError on any +91 number
return '+91 ${cleaned.substring(3, 99)} ${cleaned.substring(99)}';

// AFTER — correct slice: digits 3–7 (5-digit first group) + digits 8–12 (5-digit second group)
return '+91 ${cleaned.substring(3, 8)} ${cleaned.substring(8)}';
```

## How It Works

A 13-character `+91XXXXXXXXXX` string has:
- Index 0–2 → `+91` (the country code prefix, already removed from `cleaned` which strips `+`)

Wait — `cleaned` = `phone.replaceAll(RegExp(r'[^\d+]'), '')` which keeps the `+`. So for `+919876543210`:
- `cleaned` = `+919876543210` (13 chars)
- `cleaned.substring(3, 8)` = `98765` (5 digits)
- `cleaned.substring(8)` = `43210` (5 digits)
- Result: `+91 98765 43210` ✓

The same index bug existed in the same method in `whtasapp_calling_service.dart` (`_formatPhoneDisplay`), but there the correct indices `3, 7` and `7` were already used — only the calling screen had the bad copy.
