# L-1 — `CallManager__.swift` dead backup file with Swift syntax error

## Problem

`ios/Runner/CallManager__.swift` was a stale copy of `CallManager.swift` that was left on disk. It contained a Swift syntax error:

```swift
if let error == nil {   // ← invalid syntax: 'if let' cannot be used with '=='
```

The correct form is either `if error == nil {` or `if let error = optionalError {`.

Even though the file was not in the Xcode build target (not referenced in `project.pbxproj`), its presence was risky:
- Any future Xcode "Add Files" drag-drop could accidentally include it and cause a compile failure.
- Source-control contributors unfamiliar with the project might add it to the target.
- IDE tools (language server, SwiftLint) that scan the directory can flag it as an error.

## Fix

Deleted `ios/Runner/CallManager__.swift` from the filesystem.

```bash
rm ios/Runner/CallManager__.swift
```

The file was already excluded from the Xcode build target (no entry in `project.pbxproj`) so no project file changes were needed.

## How It Works

The only correct `CallManager` implementation is `ios/Runner/CallManager.swift` (referenced in `project.pbxproj` as `6BEB521D`). Removing the `__` backup eliminates confusion about which file is authoritative and prevents the syntax-error file from ever being accidentally compiled.
