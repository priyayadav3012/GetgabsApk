# L-5 — VoIP bundle ID env var not documented — misconfiguration silently skips all iOS VoIP pushes

## Problem

`sendApnsVoip()` read the VoIP bundle ID from an env var with a hardcoded fallback:

```php
$bundleId = env('IOS_VOIP_BUNDLE_ID', 'com.getgabs.app.ios.voip');
```

APNs VoIP pushes require a **VoIP-specific bundle ID**, which by Apple's convention is the app's main bundle ID with `.voip` appended (e.g. `com.yourapp.ios.voip`). The `apns-topic` header in the HTTP/2 request must match this bundle ID exactly — if it doesn't, APNs returns:

```
HTTP 400 TopicDisallowed  (or  BadTopic)
```

No push is delivered, with no visible error in the app.

The fallback value `'com.getgabs.app.ios.voip'` is correct for the production build of this specific app. However:
1. If the app's bundle ID changes (e.g., white-labelling, staging environment), the fallback silently sends to the wrong topic.
2. If the `.env` file on a new server deployment omits `IOS_VOIP_BUNDLE_ID`, the fallback is used without any warning — a subtle operational risk.
3. There is no corresponding documentation for the required env vars, making server setup error-prone.

## Required Environment Variables

These env vars must be set on the Laravel server for iOS VoIP push to work:

| Variable | Example value | Description |
|---|---|---|
| `IOS_VOIP_P8_KEY_PATH` | `Firebase/ios/AuthKey_XXXX.p8` | Path to `.p8` private key file (relative to `base_path()`) |
| `IOS_VOIP_TEAM_ID` | `F3Z2R4LSLD` | Apple Developer Team ID |
| `IOS_VOIP_KEY_ID` | `CRWUB2C44J` | Key ID matching the `.p8` file |
| `IOS_VOIP_BUNDLE_ID` | `com.getgabs.app.ios.voip` | VoIP bundle ID (`appBundleId + ".voip"`) |
| `IOS_APNS_SANDBOX` | `false` | `true` for dev/ad-hoc builds (see L-4) |

## Fix

Add a startup check that logs a warning if `IOS_VOIP_BUNDLE_ID` is not explicitly set (i.e., when the fallback is used):

```php
$bundleId = env('IOS_VOIP_BUNDLE_ID');
if (!$bundleId) {
    Log::warning('[SendCallFcmNotificationJob] IOS_VOIP_BUNDLE_ID not set — using default com.getgabs.app.ios.voip');
    $bundleId = 'com.getgabs.app.ios.voip';
}
```

Add all 5 vars to `config/services.php` and to the deployment checklist / `.env.example`.

## How It Works

Making the missing env var visible in logs means the next time a server is misconfigured, the warning appears immediately in the queue worker log rather than manifesting as silent push failures with no obvious cause. The long-term fix is to move the config values into `config/services.php` (which supports caching via `php artisan config:cache`) and use `config('services.ios_voip.bundle_id')` — env vars are not cached by Artisan, causing a config file read on every job dispatch.
