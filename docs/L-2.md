# L-2 — ~668 lines of commented-out old code in `whatsapp_calling_screen.dart`

## Problem

Lines 727–1393 of `whatsapp_calling_screen.dart` were entirely commented-out — a full duplicate of an older version of the file, preserved inline as `// ...` lines. This represented 668 lines of dead code (~48% of the file):

```dart
// // File: lib/ui/pages/dashboard/chats/messages_ui/whatsapp_calling_screen.dart
// import 'dart:async';
// import 'package:flutter/material.dart';
// ... (668 lines of old implementation)
// }
```

Problems caused by this:
1. **Readability**: The file was nearly twice its real size. Any developer reading or modifying the calling screen had to scroll past hundreds of dead lines to understand the structure.
2. **False diffs**: Every `git diff` on this file included the commented block, making PR reviews harder.
3. **Stale patterns**: The old code included outdated patterns (e.g., wrong substring indices, missing speaker toggle) that were already fixed. A developer could mistakenly reference the old patterns as "the way things work."
4. **IDE performance**: Large Dart files with hundreds of unused imports/symbols in comments can slow down the Dart analysis server.

## Fix

**File**: `lib/ui/pages/dashboard/chats/messages_ui/whatsapp_calling_screen.dart`

Deleted all lines from 727 to 1393 — the commented-out old implementation. The file now ends at line 725 (the closing `}` of `_WavePainter.shouldRepaint`).

```
Before: 1393 lines
After:   725 lines
```

The active implementation (lines 1–725) is unchanged.

## How It Works

Commented-out code belongs in git history, not in the file. `git log -- lib/ui/pages/dashboard/chats/messages_ui/whatsapp_calling_screen.dart` can retrieve the old implementation at any commit. Keeping it inline adds maintenance burden with no benefit.
