# L-3 — Hardcoded API key fallback in `api_end_points.dart`

## Problem

`WhatsAppCallingConfig.getBusinessApiKey()` (in `lib/domain/end_points/api_end_points.dart`) falls back to a hardcoded production API key when nothing is stored in GetStorage:

```dart
static Future<String> getBusinessApiKey() async {
    // ...
    return apiKey.isNotEmpty
        ? apiKey
        : 'PKGEG8ggXzs6xjpIDqBxlwhjIGUuvYMjDG0s7Sp9NzVBOygFUCjPHdHn'; // ← hardcoded
}
```

**Security risks:**

1. **Source code exposure**: The key is visible to anyone with access to the repository — contractors, open-source forks, decompiled APK/IPA. Once leaked, any caller can make authenticated API requests on behalf of any user.
2. **Key rotation difficulty**: Changing the key requires a new app release. If the key is compromised, it cannot be revoked without breaking all installed versions that haven't updated.
3. **Environment conflation**: The same key is used in production and any staging/dev builds that happen to not have the key stored — making it impossible to distinguish environments in server logs.

## Fix

**File**: `lib/domain/end_points/api_end_points.dart`

Remove the hardcoded fallback. Return an empty string and let the caller handle the missing key case:

```dart
// BEFORE — hardcoded fallback
return apiKey.isNotEmpty
    ? apiKey
    : 'PKGEG8ggXzs6xjpIDqBxlwhjIGUuvYMjDG0s7Sp9NzVBOygFUCjPHdHn';

// AFTER — empty string; caller checks and handles gracefully
return apiKey;
```

Any call site that receives an empty `apiKey` should abort and log a warning rather than sending an authenticated request with an empty key. If a guest/unauthenticated mode is needed, that should be a deliberate, separate code path — not a silent fallback to a production credential.

**Additionally**: rotate the exposed key. Even if the fix is applied, the old key value (`PKGEG8gg...`) is in git history and must be considered compromised. Issue a new key via the API management console and update all authenticated devices.

## How It Works

Removing the fallback forces `getBusinessApiKey()` to return `""` when no key is stored. The existing early-return guards in callers (`if (apiKey.isEmpty) return;`) already handle this correctly — the call setup is aborted rather than proceeding with an invalid or leaked credential.
