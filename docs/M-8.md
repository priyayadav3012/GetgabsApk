# M-8 — APNs JWT and FCM access token regenerated on every job dispatch — unnecessary latency

## Problem

Every time `SendCallFcmNotificationJob` ran, it fetched a fresh Google OAuth2 access token from the network:

```php
$client = new Client();
$client->setAuthConfig($serviceAccountPath);
$client->addScope('https://www.googleapis.com/auth/firebase.messaging');
$client->useApplicationDefaultCredentials();
$notiftoken  = $client->fetchAccessTokenWithAssertion();
$accessToken = $notiftoken['access_token'] ?? null;
```

`fetchAccessTokenWithAssertion()` makes an HTTPS POST to `accounts.google.com/o/oauth2/token` every call. This adds ~150–300 ms to every job. Google issues tokens with a 60-minute TTL — the same token is valid for all FCM calls within that window. Fetching a new one per job wastes network time, risks Google's token endpoint rate limiting, and unnecessarily increases job latency (critical for real-time call signalling).

A similar issue exists for the APNs JWT (built by `buildApnsJwt()`): ES256 signing is fast, but the JWT has a 55-minute validity window. Without caching it, a new RS256/ES256 signing operation runs on every push.

## Fix

**File**: `SendCallFcmNotificationJob.php`

Cache the FCM access token in Laravel Cache for 55 minutes (5-minute safety margin before the 60-minute Google TTL expires):

```php
// BEFORE — fresh network call per job
$client = new Client();
// ...
$accessToken = $client->fetchAccessTokenWithAssertion()['access_token'] ?? null;

// AFTER — one network call per hour, cached in Laravel Cache
$accessToken = Cache::remember('fcm_access_token', 55 * 60, function () {
    $client = new Client();
    $client->setAuthConfig(base_path('Firebase/cert.json'));
    $client->addScope('https://www.googleapis.com/auth/firebase.messaging');
    $client->useApplicationDefaultCredentials();
    $notiftoken = $client->fetchAccessTokenWithAssertion();
    return $notiftoken['access_token'] ?? null;
});
```

Added `use Illuminate\Support\Facades\Cache;` import.

## How It Works

`Cache::remember($key, $ttl, $callback)` returns the cached value if it exists and has not expired; otherwise it executes `$callback`, stores the result, and returns it. All queue workers on all servers share the same cache (Redis or database, depending on the `CACHE_DRIVER` env). The first job in each 55-minute window pays the token fetch cost; all subsequent jobs in the same window return in microseconds. For a deployment receiving 100 calls/hour, this removes 99 unnecessary token fetches per hour. For real-time call signalling, it also shaves ~200 ms off the critical path for every call (the job is dispatched at the moment the caller dials — any latency here is directly perceived by the callee waiting for their phone to ring).
