# H-4 — Speaker toggle is UI-only — no actual audio routing change

## Problem

`_toggleSpeaker()` in `WhatsAppCallingScreen` updated the button's visual state but never changed where the audio was routed:

```dart
void _toggleSpeaker() {
    setState(() => _isSpeaker = !_isSpeaker);
    HapticFeedback.lightImpact();
    // ← nothing called to actually switch audio output
}
```

Tapping the speaker button showed it as "active" (highlighted) but the audio continued playing through the earpiece. On iOS this was especially confusing because CallKit had already set the audio session to `voiceChat` mode, which defaults to earpiece routing, and nothing overrode that.

## Fix

**File**: `lib/ui/pages/dashboard/chats/messages_ui/whatsapp_calling_screen.dart`

Call `Helper.setSpeakerphoneOn(bool)` from `flutter_webrtc` immediately after updating the state:

```dart
// BEFORE — UI only, no audio change
void _toggleSpeaker() {
    setState(() => _isSpeaker = !_isSpeaker);
    HapticFeedback.lightImpact();
}

// AFTER — actually routes audio to/from speaker
void _toggleSpeaker() {
    setState(() => _isSpeaker = !_isSpeaker);
    Helper.setSpeakerphoneOn(_isSpeaker);
    HapticFeedback.lightImpact();
}
```

The `flutter_webrtc` package import was added to the file:

```dart
import 'package:flutter_webrtc/flutter_webrtc.dart';
```

## How It Works

`Helper.setSpeakerphoneOn(true)` calls `AVAudioSession.sharedInstance().overrideOutputAudioPort(.speaker)` on iOS, which routes audio to the loud speaker regardless of the current session category. `setSpeakerphoneOn(false)` restores the default routing (earpiece for `voiceChat` mode, or system default). Because `CallManager` uses `useManualAudio = true`, the WebRTC engine defers audio routing to the app — `Helper.setSpeakerphoneOn` is the correct API to change routing without re-activating the session.
