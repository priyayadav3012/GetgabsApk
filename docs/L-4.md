# L-4 — APNs endpoint hardcoded to production — sandbox devices never receive VoIP pushes

## Problem

`SendCallFcmNotificationJob.sendApnsVoip()` always sent to the APNs production endpoint:

```php
$apnsHost = 'https://api.push.apple.com';
```

Apple operates two separate APNs environments:
- **Production**: `api.push.apple.com` — for App Store / TestFlight builds
- **Sandbox**: `api.sandbox.push.apple.com` — for development / simulator / ad-hoc builds

A device running a debug or ad-hoc build is provisioned with a **sandbox** VoIP push certificate/entitlement. Sending to the production endpoint with a sandbox device token returns:

```
HTTP 400 BadDeviceToken
```

This silently fails — no VoIP push is delivered. Developers testing on physical devices with `flutter run` or an ad-hoc build would see no incoming call notification, making the feature appear broken in development even when the code is correct.

## Fix

**File**: `SendCallFcmNotificationJob.php`

Add an env var `IOS_APNS_SANDBOX` that selects the endpoint:

```php
$isSandbox = (bool) env('IOS_APNS_SANDBOX', false);
$apnsHost  = $isSandbox
    ? 'https://api.sandbox.push.apple.com'
    : 'https://api.push.apple.com';
```

In `.env`:
```ini
# Development / ad-hoc builds
IOS_APNS_SANDBOX=true

# Production (App Store / TestFlight)
IOS_APNS_SANDBOX=false
```

**Alternatively** (more robust): read the `aps-environment` entitlement embedded in the device token's certificate to auto-detect the environment. However, the env-var approach is simpler and sufficient for most deployments.

## How It Works

APNs routes pushes based on the environment the device token was issued in. Production tokens are invalid on the sandbox server and vice versa. The `IOS_APNS_SANDBOX` flag lets the same job code serve both environments by switching the host. Set `IOS_APNS_SANDBOX=true` on staging/development server instances and `false` (or omit) on production.
