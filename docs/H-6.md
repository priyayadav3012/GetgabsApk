# H-6 — `initializeCallListener()` in `onNativeCallAnswered` tears down the service mid-answer

## Problem

When the user answered a call from CallKit in killed/background state, `onNativeCallAnswered` ran:

```dart
await initializeCallListener();   // ← unconditional teardown + reinit
final svc = GlobalCallListenerService.instance.service;
if (svc != null) {
  svc.setPendingCall(callId: callId2, sdp: sdp2);
}
storePendingNavigation({...});
if (isAppInForeground) {
  await handlePendingCallNavigation();   // → navigates to WhatsAppCallingScreen
}
```

`initializeCallListener()` calls `GlobalCallListenerService.instance.initialize()`. Inside `initialize()`:

```dart
// From GlobalCallListenerService.initialize():
if (_service != null) {
  await _service!.cleanupCall();      // ← wipes hasActivePendingCall
  _service!.socket?.disconnect();
  _service = null;
}
_service = WhatsAppCallingService(...);
await _service!.initialize();         // ← new service, no pending call set
```

If a service already existed (from the earlier `onIncomingVoipCall` handler or `_checkInitialCall`), `cleanupCall()` was called, which:
- Set `_hasActivePendingCall = false`
- Removed all `pending_*` SharedPreferences keys
- Cleared `incomingSdp`, `currentCallId`, etc.

Then `setPendingCall` ran on the *new* service — correct. But `WhatsAppCallingScreen._initCall()` ran a moment later, and if *anything* re-triggered `initializeCallListener()` between those two points (e.g., `_checkInitialCall` completing its 1.5 s delay, or `_initializeCallListener` completing its 2 s delay), the service was torn down again, this time with `setPendingCall` never being called on the new instance. `hasActivePendingCall` stayed `false`, `answerCall()` fell into the prefs-recovery path, but prefs were already wiped by `cleanupCall()`, so `_handleCallEnded('Call expired')` fired.

## Fix

**File**: `lib/domain/end_points/api_end_points.dart`

Only initialise if no service exists. If a service already exists, just reconnect the socket instead of tearing everything down:

```dart
// BEFORE — always called initializeCallListener() which tears down the service
await initializeCallListener();

// AFTER — reuse existing service, only reconnect socket if needed
final existingSvc = GlobalCallListenerService.instance.service;
if (existingSvc == null || !GlobalCallListenerService.instance.isInitialized) {
  await initializeCallListener();
} else if (existingSvc.socket?.connected != true) {
  existingSvc.socket?.connect();
  debugPrint('🔄 onNativeCallAnswered: socket reconnected, service reused');
}
```

## How It Works

`GlobalCallListenerService.initialize()` already has a guard that skips teardown when `hasActivePendingCall` or `isCallActive` is true. However, those flags are only set *after* `setPendingCall` runs — and `setPendingCall` only runs *after* `initializeCallListener()` returns. So the guard never fired in this race. 

The fix moves the guard to the call site: if the service exists, leave it intact and only fix the socket connection. `setPendingCall` then runs on the already-initialised service with `hasActivePendingCall` set correctly, and `WhatsAppCallingScreen._initCall()` finds a service with a live pending call.
