# C-1 — `flutter.` prefix mismatch: AppDelegate writes invisible to Flutter SharedPreferences

## Problem

`shared_preferences` on iOS (package `shared_preferences_foundation` v2.x) prepends the string `"flutter."` to every key before writing it to `NSUserDefaults`. So when Dart calls:

```dart
prefs.getString('pending_call_id')
```

the plugin actually reads the NSUserDefaults key `"flutter.pending_call_id"`.

`AppDelegate.swift` was writing call metadata with plain keys:

```swift
defaults.set(callId, forKey: "pending_call_id")          // stored as "pending_call_id"
defaults.set(callerName, forKey: "pending_caller_name")   // stored as "pending_caller_name"
// ...
```

Flutter looked for `"flutter.pending_call_id"` and always found `nil`. The entire killed-state and locked-phone recovery flow — which depends on reading `pending_call_id`, `pending_call_session`, `pending_caller_name`, `pending_caller_number`, and `pending_callkit_id` from SharedPreferences after a VoIP push — silently returned empty strings on every attempt.

The app appeared to work because the FCM background isolate (`_firebaseMessagingBackgroundHandler`) *also* writes the same keys via `SharedPreferences` (with the correct `flutter.` prefix). If FCM arrived before the user tapped Answer, the Flutter reads found the FCM-written values. When FCM was slow or the user answered quickly, the call fell into `_handleCallEnded('Call expired')`.

## Fix

**File**: `ios/Runner/AppDelegate.swift`

```swift
// BEFORE
let defaults = UserDefaults.standard
defaults.set(callId,      forKey: "pending_call_id")
defaults.set(callerName,  forKey: "pending_caller_name")
defaults.set(callerNumber,forKey: "pending_caller_number")
defaults.set(uuidString,  forKey: "pending_callkit_id")
if !sessionRaw.isEmpty {
    defaults.set(sessionRaw, forKey: "pending_call_session")
}
defaults.synchronize()

// AFTER
let defaults = UserDefaults.standard
defaults.set(callId,      forKey: "flutter.pending_call_id")
defaults.set(callerName,  forKey: "flutter.pending_caller_name")
defaults.set(callerNumber,forKey: "flutter.pending_caller_number")
defaults.set(uuidString,  forKey: "flutter.pending_callkit_id")
if !sessionRaw.isEmpty {
    defaults.set(sessionRaw, forKey: "flutter.pending_call_session")
}
// Note: synchronize() removed — deprecated since iOS 12; writes are persisted automatically.
```

## How It Works

`shared_preferences_foundation` calls `UserDefaults.standard.set(value, forKey: key)` where `key` is the Dart key with `"flutter."` prepended. By mirroring that prefix in AppDelegate, both sides now read and write the same physical key in `NSUserDefaults`. The VoIP push delivery path (AppDelegate) and the FCM path (`_firebaseMessagingBackgroundHandler`) now write to the same location that Flutter's `SharedPreferences.getInstance()` reads — making killed-state and locked-phone call recovery reliable without depending on FCM arrival timing.
