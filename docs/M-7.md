# M-7 — Second FCM send unconditional — `sub-user0` topic leaks call events to wrong users

## Problem

The job always sent two FCM messages: one to `user{userId}` and one to `sub-user{subUserId}`:

```php
$this->sendFcm($fcmUrl, $message, $accessToken);          // → "user123"

$message['message']['topic'] = $user2topic;
$this->sendFcm($fcmUrl, $message, $accessToken);          // → "sub-user0" when subUserId=0
```

FCM topics follow a publish/subscribe model. Any device that has subscribed to the topic receives the message. `"sub-user0"` is a valid FCM topic string, and if **any** device in the app has ever subscribed to `"sub-user0"` (e.g. because a user's sub-user ID defaulted to 0 during registration), every such device receives the call push.

This means:
- A call intended for user 123 could be delivered to unrelated users whose `subUserId` happened to be 0.
- Those users' devices would ring with an incoming call that belongs to someone else.
- The call would fail when their app tries to join (wrong `from_user_id`, wrong socket room), but the UX impact (unexpected ringing) is severe.

## Fix

**File**: `SendCallFcmNotificationJob.php`

Guard the second FCM send with `$this->subUserId > 0`:

```php
// BEFORE — always sent two FCMs
$this->sendFcm($fcmUrl, $message, $accessToken);
$message['message']['topic'] = $user2topic;
$this->sendFcm($fcmUrl, $message, $accessToken);

// AFTER — second send only when a valid sub-user exists
$this->sendFcm($fcmUrl, $message, $accessToken);
if ($this->subUserId > 0) {
    $message['message']['topic'] = $user2topic;
    $this->sendFcm($fcmUrl, $message, $accessToken);
}
```

## How It Works

`$this->subUserId` is `0` when the job is dispatched for a user who has no associated sub-user account. Skipping the second FCM send in that case avoids the `"sub-user0"` topic entirely. The primary user's notification (`"user{userId}"`) is still delivered. When `subUserId > 0` the behaviour is unchanged.
