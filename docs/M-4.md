# M-4 — `retriggerVoipRegistration()` creates a brief nil gap — incoming VoIP push lost

## Problem

`retriggerVoipRegistration()` tore down the old registry before constructing the new one:

```swift
private func retriggerVoipRegistration() {
    voipRegistry = nil          // 1. old registry deallocated immediately
    voipRegistry = PKPushRegistry(queue: DispatchQueue.main)  // 2. new registry
    voipRegistry?.delegate = self
    voipRegistry?.desiredPushTypes = [.voIP]
}
```

Between line 1 (`voipRegistry = nil`) and line 4 (`desiredPushTypes = [.voIP]`), `voipRegistry` is either `nil` or a `PKPushRegistry` that has not yet registered with Apple's VoIP push infrastructure. If a VoIP push arrived in this window (unlikely but possible on slow devices under load, or when the server retries a failed push), it would be delivered with no registered delegate and silently dropped.

Additionally, iOS may immediately fire `didUpdate pushCredentials` when `desiredPushTypes` is set on the new registry. If the `delegate` was set to `nil` for even one run-loop cycle between lines 1 and 3, the `didUpdate` callback would not fire and the cached VoIP token would never be updated.

## Fix

**File**: `ios/Runner/AppDelegate.swift`

Build the new registry fully before releasing the old one. Assigning the completed new registry to `voipRegistry` releases the old one atomically — there is no nil gap.

```swift
// BEFORE — nil gap between teardown and setup
private func retriggerVoipRegistration() {
    voipRegistry = nil                                         // ← gap starts here
    voipRegistry = PKPushRegistry(queue: DispatchQueue.main)  // ← gap ends here
    voipRegistry?.delegate = self
    voipRegistry?.desiredPushTypes = [.voIP]
}

// AFTER — new registry is fully configured before old one is released
private func retriggerVoipRegistration() {
    let newRegistry = PKPushRegistry(queue: DispatchQueue.main)
    newRegistry.delegate = self
    newRegistry.desiredPushTypes = [.voIP]
    voipRegistry = newRegistry  // old registry released only after new one is set
}
```

## How It Works

Swift ARC guarantees that the old `voipRegistry` is released only when its reference count drops to zero. By constructing the new registry first and storing it in a local `let`, the local holds a strong reference throughout setup. The assignment `voipRegistry = newRegistry` decrements the old object's refcount (deallocating it) and increments the new object's simultaneously — an atomic swap with no window where the property is nil. `PKPushRegistry` immediately calls `didUpdate pushCredentials` on the delegate when `desiredPushTypes` is set, and the delegate is already set at that point.
